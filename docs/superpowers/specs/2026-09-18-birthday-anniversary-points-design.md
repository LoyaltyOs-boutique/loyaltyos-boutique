# Birthday/Anniversary Automatic Points — Design

**Problem:** The merchant configures per-tier birthdayBonus/anniversaryBonus rates (with per-tier on/off toggles) in the Points Ledger UI, but no code anywhere reads these fields to credit a customer. The only way a customer currently gets birthday/anniversary points is a merchant manually opening a separate Points Tool and typing a number by hand — completely disconnected from the Approve & Send action and from the configured rate.

**Fix:** extend `recordMessageAction` (convex/customers.ts) — the single mutation both the primary ("Approve & Send", wa.me link) and secondary ("Send via Cloud API instead") buttons already call on success — so that, immediately after it inserts the message_actions row, it ALSO credits the customer's points using the exact same tier-aware, live-settings-read pattern reviews.ts's approveReview now uses (read the real settings document at the correct path, check the customer's tier's own `on` toggle, use that tier's birthdayBonus/anniversaryBonus rate when enabled, otherwise fall back to global's rate) — but ONLY when the action being recorded is a send outcome ("sent" or "link_opened"), never for "cancelled". Use `occasion` (already an argument: "birthday" or "anniversary") to pick the correct field name.

**Idempotency:** recordMessageAction already has an existing dedup/idempotency check preventing more than one decision per (customer_id, occasion, occasion_date) tuple — read the real existing check before writing anything, and rely on it rather than adding new duplicate-prevention logic; if that check does not exist or does not cover this exactly, stop and report back rather than guessing.

**Architecture must NOT be touched by this task:** convex/auth.ts, requireMerchantSession, the whatsapp_consent gate, sendWhatsAppTemplateMessage/postToGraphApi (the real Cloud API send call in convex/whatsapp.ts), convex/crons.ts, convex/ai.ts. This task only adds a points-credit side-effect inside recordMessageAction's existing handler — it does not change what gets sent, how, or when.
