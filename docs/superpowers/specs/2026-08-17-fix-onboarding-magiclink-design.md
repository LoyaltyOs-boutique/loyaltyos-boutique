# Design: Fix Onboarding Magic Link for Existing Customers

## Context
Current onboarding flow returns `{ok: false, error: "This WhatsApp number already has a profile", existingId}` for existing customers. Frontend components `Onboarding.jsx` and `Join.jsx` interpret this as an error and trigger a redundant manual magic-link generation flow, which is brittle.

## Proposal
Update `convex/customers.ts` to return `{ok: true, isExisting: true, existingId, customer}` for registered numbers instead of an error.

- `ok: true` ensures frontend proceeds to success path.
- `isExisting: true` + `existingId` provides metadata (though the success path is unified).
- Frontend components `Onboarding.jsx` and `Join.jsx` success path will receive the result and display the magic link generated by `onboardCustomerRemote` seamlessly.

## Design Decisions
- `createCustomer` (convex/customers.ts) updated to return `{ ok: true, isExisting: true, existingId, customer }` for existing numbers.
- Frontend logic for manual error recovery becomes unreachable or can be cleaned up as a follow-up, but the success path handles existing customers via `onboardCustomerRemote` logic.
- Maintains "one WhatsApp number = one profile" constraint (no new row inserted).

## Verification
- Registered number -> UI displays magic link, no error.
- Invalid number -> UI displays error (unchanged).
- New number -> UI displays magic link (unchanged).
