# Combined-Occasion AI Draft — Design

**Problem:** today's combined-message UI (Today View feature) joins two independent single-occasion AI drafts with a literal separator string. The AI itself never sees "this customer has both occasions today" — it writes two unrelated single-occasion messages that get stitched together, not one coherent combined wish.

**Fix:** add a new, separate function — does NOT modify `generateMessageDraft`, `generateMessageDraftPublic`, or `generateMessageDraftManual`, and does NOT touch any of their 9 existing hardcoded `occasion: v.union(v.literal("birthday"), v.literal("anniversary"))` call sites (`convex/ai.ts`, `convex/crons.ts`, `convex/schema.ts`) — those stay exactly as they are, serving the tomorrow tabs and every single-occasion case unchanged.

1. `convex/ai.ts`: new `internalAction` `generateCombinedMessageDraft(customerName, tier)` — no `occasion` arg at all (a combined draft is always "birthday + anniversary", there's no third combination in this schema). Reuses, unmodified: `callGemini`, `DATA_NOT_INSTRUCTIONS_NOTICE`, `wrapUntrustedField`, `truncateForPrompt`, `sanitizeGeminiOutput`, `PROMPT_FIELD_MAX`. New prompt text (structured identically to `generateMessageDraft`'s existing prompt, same sentence-array-join style): instructs Gemini to write ONE warm message wishing both birthday and anniversary together in the same natural message (2-4 sentences total, luxury tone, not two messages stitched together), addressing the customer by name and reflecting their tier — no `occasion` field wrapped into the DATA section since it's implicit.
2. `convex/ai.ts`: new public `action` `generateCombinedMessageDraftPublic(userId, token, customerName, tier)` — merchant-session-gated via the same `checkMerchantSession` pattern `generateMessageDraftPublic` uses, calls `generateCombinedMessageDraft` via `ctx.runAction`. NO caching — call live every time, same "no clean cache key" posture as the existing `generateMessageDraftManual` (`ai.ts:590-606`), which is the established precedent for this exact situation. Explicitly do NOT touch `ai_message_drafts`' schema or index — this function never reads or writes that table.
3. `src/lib/db.js`: new bridge `generateCombinedMessageDraftRemote(customerId, customerName, tier)` mirroring `generateMessageDraftRemote`'s exact shape/error-handling (resolve to `null` on any failure, never throw), calling `api.ai.generateCombinedMessageDraftPublic`.
4. `src/pages/merchant/Customers.jsx`: in `ApprovalModal`, when `combined` is true, replace the current two `useEffect`s (the birthday-draft effect firing with a hardcoded `'birthday'` occasion, and the second anniversary-only effect) and the `combinedPreviewText` concatenation (`` `${previewText}\n\n— — — — —\n\n${anniversaryPreviewText}` ``) with ONE new effect that calls `generateCombinedMessageDraftRemote` once, and use its result directly as the combined preview/send text (with a combined fallback template if the AI call fails/returns null — reuse the existing single-occasion fixed-template style, adapted to mention both occasions, rather than inventing new copy from scratch). The single-occasion (non-combined) modal path is completely unchanged — same effect, same `previewText`, same `fallbackPreviewText` as today.

**Explicitly NOT touched:** `generateMessageDraft`, `generateMessageDraftPublic`, `generateMessageDraftManual`, `ai_message_drafts` schema/caching, `convex/crons.ts`, the "tomorrow" tabs, the single-occasion-today path, `recordMessageAction`/points-crediting logic (already correct, called the same way regardless of how the message text was produced).
