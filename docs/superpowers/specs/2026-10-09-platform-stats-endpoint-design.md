Title: 85 Lansdowne read-only stats endpoint for the LoyaltyOS Platform Admin (Phase 2B)
Goal: Let the platform admin read boutique-level numbers from 85 Lansdowne every 15 minutes through one secret-protected, read-only HTTP endpoint, without changing anything that exists.
Evidence: Phase 2 read-only audit of 2026-10-08 (kept in the platform admin repo as docs/reference/phase2-audit-2026-10-08.md): no convex/http.ts exists; metric sources and live values per field; session_last_seen is cleared on logout; per-query limits are far above today's table sizes.
Decisions (approved by the user):
1. Only two new files: convex/http.ts (router) and convex/platformStats.ts (internal query). No existing file, table, index or function changes. convex/_generated updates as Convex regenerates it.
2. Route: GET /platform/stats on the deployment's .convex.site address. Other methods are not routed.
3. Access: the request must carry "Authorization: Bearer <secret>". The secret lives only in the environment variable PLATFORM_STATS_SECRET (set by the user, never in code or logs). Missing variable: 503. Missing or wrong header: 401 with no detail. The comparison runs in constant time over equal-length strings.
4. The handler calls one internalQuery and returns JSON with Cache-Control: no-store. No CORS headers (server-to-server only). It never writes anything.
5. Test customers: customer users whose name matches /test|ztest|demo|sample|dummy/i are excluded, together with their reviews, activity events, ledger rows and orders. Soft-deleted customers are excluded. Known limit: about 6 test records do not match the pattern.
6. Response fields (aggregates only, never names, mobiles, emails or text): schemaVersion 1; generatedAt (ms); customersActive; testCustomersExcluded; reviewsApproved (approved reviews of every type); pointsIssued (positive ledger deltas plus orders.points_earned plus approved reviews.points_awarded); weeklyHistory (7 objects of date YYYY-MM-DD in IST and count of customer_activity_events, oldest first, ending today IST); weeklyUses (sum of weeklyHistory); ownerOnlineAt (newest merchant session_last_seen while a session is live, else null); ownerLastActionAt (newest of points_ledger.created_at created by admin, orders.created_at, message_actions.decided_at, events.created_at, lookbooks.created_at, settings.updated_at, catalogue_items _creationTime; null if none); firstRecordAt (earliest users _creationTime).
7. Name, city, owner, plan, status, subscription, joined date and top reward are not served here; the platform keeps them in its own registry (Phase 2C).
8. Deploy: this repo has one Convex deployment, pleasant-cobra-560, which is live. "npx convex dev --once" runs once, only after confirming .env.local names pleasant-cobra-560. Until the user sets PLATFORM_STATS_SECRET the endpoint answers 503.
Known limits: the test-customer pattern is heuristic; ownerOnlineAt only shows a live session; the platform samples it every 15 minutes; a full scan of small tables per call (far below Convex limits today).
Test plan: no header, a wrong secret and a POST are refused; with the right secret the JSON has exactly the fields above and no personal data; the numbers match an independent recount from npx convex data; git diff shows only the two new convex files, the regenerated _generated files and the spec; function-spec grows only by the new entries; requireMerchantSession count stays 62; convex/auth.ts and convex/schema.ts have an empty diff; ONE_DEVICE_LOCK stays on.
END OF DESIGN.
